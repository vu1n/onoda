# Assumptions register

Tracked project artifact required by `docs/handoff/SOURCE_NOTES.md` ("Initial
assumptions register") and `docs/handoff/SOL_PI_DELTA.md` §6. This is the
single place unresolved reconstruction decisions and M1 implementation
assumptions are tracked with a status and an owning milestone. Do not resolve
an item here by inventing a threshold, SDK method, or benchmark membership
(AGENTS.md rule 10); resolve it by inspecting the source and recording the
evidence, or leave it `unresolved`.

Status values: `unresolved` (not decided), `assumed` (a working default is in
force and must be revisited), `decided` (settled for the current milestone,
recorded here for traceability), `pinned` (see `provenance/sources.json` for
the resolved revision).

add or update the matching entry in `provenance/sources.json`) instead of
deleting the row; keep the row so the history of the decision is visible.

| A50 | How are Pi runs sandboxed? | decided | Bubblewrap (`bwrap`), Linux only; anything else refuses a sandboxed or live run, never degrades. Two layers of allowlisted bind mounts. Outer (the whole Pi process tree, RLM children included): system dirs, the pinned runtime, node, the Python environment, the RLM kernel dir and CA files read-only; the run's Pi work dir read-write; the task bundle read-only; private `/tmp`, `/proc`, pid/ipc/uts namespaces; the network stays on because Pi must reach its provider. Inner (Pi's `bash` tool, so Action Fusion's `then_run`, and the RLM kernel): no network, cleared environment (no credential), the workspace read-write, the bundle read-only, an empty `/proc`; wired through Pi's `settings.json` `shellPath` and the kernel's interpreter variable, with `defaultProjectTrust: never` so a workspace `.pi/settings.json` cannot undo it. Known limits: the file-tool check has a time-of-check gap (a symlink swapped after the check); the outer layer's network is open, so an agent that got code running in the Pi process itself could reach any host; the inner layer has no `/proc`; replay stays unsandboxed (it runs no model and no agent command reaches a live tool). | A60 | How is a Pi run sandboxed on macOS? | decided (owner confirmed the single layer by merging PR #20, 2026-10-03) | ORCA runs only on the owner's Mac, so live runs need a sandbox there. `SeatbeltSandbox` (`sandbox-exec` profiles) has one layer, not bwrap's two (A50): macOS 27 refuses to apply a second Seatbelt sandbox inside a deny-default one (`sandbox_apply: Operation not permitted`; repro: `sandbox-exec -p '(version 1)(deny default)(allow process-exec process-fork)(allow file-read*)' sandbox-exec -p '(version 1)(allow default)' /bin/echo x`), and Pi must start the inner wrappers.
