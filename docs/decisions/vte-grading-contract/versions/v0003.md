## Grade each claimed state from the one job it cites, and identify it only by printed irrep

A reported excitation energy is `supported` only when the cited job, executed or cache-hit in this run, prints that value for a state of the claimed spin (and irrep, when printed) in its transition table. Energies subtracted across two jobs are never accepted. A supported claim identifies a reference row only if that job printed irreps (ran with symmetry) and its identity character (`normalize_character` with a Rydberg p orbital's axis dropped) picks exactly one row of the claimed (spin, irrep), by the row's own character or one of its recorded aliases, even when that is the only such row. The grader is evaluator version 4. Both arms are told this contract in the task instruction.

**Why.** Without one cited job the grader cannot check the number came from a converged calculation of that state; without a printed irrep the identification rests on the agent's own label.

### Invariant
- `_grade_value` contradicts a value not printed for that spin/irrep in the cited job; a job this run did not execute or hit is `unsupported`; a parser problem in `mr_states`/`casscf_converged` is `unsupported`; a CASSCF-only match is `contradicted` (`casscf_value`).
- A job without printed irreps makes the claim `unidentified` with reason `irrep_not_printed` (A71).
- Rows that two claims land on are identified by neither; nothing is paired by energy order.
- `_candidates` requires the character to pick the row, even for the only row of its spin and irrep. A bare or different label is `unidentified` with reason `character`.
- `identity_character` drops a Rydberg p orbital's axis (`n,3pz` and `n,3p` compare equal); reference keys and reports keep the full `normalize_character` text.
- A reference row may carry `aliases` (other characters for the same state) and then carries `notes` saying why; a row's character may be corrected from its printed label only by an erratum in `scripts/questdb_cases.py`, recorded in `notes`. Grading refuses references where two rows of one spin and irrep accept the same character.
- First uses (ratified 2026-10-25): the four QUESTDB rows whose pi glyph reads as a bare `p` (ketene 1A2, 3A1; diazomethane 1A1, 3A1), corrected from QUESTDB's MAIN tables; thioacetone's sulfur Rydberg rows accept `n,4s` / `n,4p`.
- Each identified row also carries an accuracy verdict against the draft decision vte-energy-tolerance. `vte report` adds `accurate` and `runs_without_claim` per arm.
- `VTE_INSTRUCTION` tells both arms that a state is matched by spin, irrep and character together.
- `VTE_INSTRUCTION` states the contract identically for both arms (A73).
- `vte report` pools runs per A63 and declares no winner.
- Irreps are compared after `normalize_irrep` (prime glyphs only); no per-molecule B1/B2 remapping exists (A64).

#### A58: How is a reported VTE graded?

Register status: decided (default, QUESTDB slice). Owner milestone: QUESTDB slice.

Each claimed state names spin, irrep, character and the job it was read from. The value must be printed for a state of that spin (and irrep, when the output prints one) in that job's output, else `contradicted`; a job this run did not execute or hit in the cache makes the claim `unsupported`. It is *identified* only when (spin, irrep) picks exactly one reference row, or the normalized character label picks exactly one among several; anything else is `unidentified` and never paired by energy order (the paper's rule). References come from QUESTDB's `data/cas/json` SC-NEVPT2 column, live in an evaluator-only `references.json` the manifest pins by sha256, and are never staged or committed to the agent store. Coverage, MAE over identified states and false-success counts are reported.

#### A63: How does `onoda vte report` pool runs and compare two arms?

Register status: decided (default, QUESTDB slice). Owner milestone: QUESTDB slice.

An arm is a run's variant. Per arm: identified reference rows summed over its runs against all rows of those runs (`coverage`), MAE over every identified row of every run, and the summed false-success claims, from each run's latest `vte-claims` evaluation. The common-target MAE between two arms uses only targets (case, reference row) each arm identified in at least one run, averages an arm's repeats per target first, then averages over targets, so both arms are measured on the same states with equal weight per state. Means are decimal text rounded half-even to 6 places; a mean over nothing is `unresolved`. The report states counts and errors and declares no winner; any synthetic run makes it synthetic.

#### A64: Does the claimed irrep mean the same thing in ORCA's output and in QUESTDB?

Register status: unresolved (open risk, QUESTDB slice). Owner milestone: QUESTDB slice.

The grader requires a claimed state's irrep to match both the irrep ORCA prints for it and QUESTDB's row. For planar C2v molecules, B1 and B2 depend on the axis orientation, and ORCA's symmetry frame and QUESTDB's convention can disagree, so a correct calculation could fail to be identified. Phase 0c showed ketene's 1B1(π,3s) matching, so at least that case agrees. To be checked per molecule on the Mac before the experiment. No silent remapping: a mapping, if one is needed, is explicit per case and recorded in its manifest.

#### A71: Does a supported claim from a job without printed irreps identify a target?

Register status: decided (owner chose "Require it", 2026-10-03, after the first live ketene run). Owner milestone: irrep printed.

No. A claim is still graded `supported` when the cited job prints its value at the claimed spin, but it is identified with a reference row only if that job's output prints irreps (ORCA with point-group symmetry); otherwise it is `unidentified` with reason `irrep_not_printed`. In the first live ketene run (2026-10-03) all three identified states came from jobs without symmetry, so their irreps were the agent's labels alone. `report_vtes` tells the agent to cite a job run with symmetry. A64's B1/B2 convention risk applies to the printed irreps.

#### A73: What are the agents told about how a VTE claim is graded?

Register status: decided (default, pending the owner's choice; both arms alike). Owner milestone: grading contract.

The task instruction states the grading contract: a value counts only if the one cited job prints it in its SC-NEVPT2 transition energy table with the state's irrep, so jobs are state-averaged with symmetry on, and differences of total energies across separate jobs are not reported. Why: in the stopped 8-molecule run (2026-10-04), 5 of the 6 acetaldehyde claims were total-energy differences between single-root jobs, which the grader (A58, A71) cannot accept, so the runs measured the reporting format rather than the chemistry. Both arms get the same sentence; the paper's setup may not have stated it.
